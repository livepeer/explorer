Orchestrator State Whether new stake would earn more here. Fees vs stake Share of network fees vs share of network stake over the last 7 settled rounds. Those trailing shares compare nodes. Reward cap New LPT over those 7 rounds. Each round is capped at the smaller of that round’s fee share and stake share, then the capped rounds are added up. Not the smaller of the two trailing totals. Forecasted yield A rough estimate of what 150 LPT would earn over one year, using today’s numbers. It can differ from what you actually earn. Sort stays on trailing fee vs stake. Delegated stake All the LPT currently delegated to this node. Trailing 90D fees Fees this node earned over the past 90 calendar days, in USDC. A hint at how steady its work is. Loading state mirrors row height:
  • Labels: “Room to earn,” “Full,” and “Balanced” name what happens if you stake here. A “caps rewards” tag marks the limiting side so the ceiling is visible at a glance.
  • Filter: “Earning now” keeps the list focused on nodes with real activity. “All nodes” keeps every address reachable when you need a specific one. It only changes which nodes appear. The columns stay the same.
  • Familiar numbers: Forecasted yield, Delegated stake, and Trailing 90D fees stay after the decision columns. Stake amounts use the green LPT mark. Fee amounts use the USDC mark. Column order is the hierarchy. Yield is a guess from current shares, so it informs the choice but never sets the order. On narrower laptops the quietest columns drop first (Node keeps, then 90D fees, then Delegated stake). Yield stays.

Design decisions on this mockup

  • Network shares. How much new LPT the network mints is still being finalized, so these screens show how far a node’s reward ceiling can still move (for example from 2.3% toward 11.8%). That keeps the compare about opportunity while emissions settle.
  • Seven settled rounds. The list defaults to the last week of settled work. That window is harder to game, and it lines up with when rewards are paid. Per-round receipts are 803 on History · Rewards.
  • Room to earn / Full / Balanced. Those names speak to the stake choice on the compare list. Under 2.0 the old “Active” label loses its meaning with the capped set. On /delegating, the same stake-capped state reads “You’re earning” instead: the user already bonded, so the copy is about their stake.
  • Fee and stake only. Honesty scores and validator set design ( 804) are out of scope. This review is about where stake still earns.
  • Same controls as the rest of Explorer. Delegate and the amount action are the product button. Focus is a green ring. The phone list and the day-one steps each sit in one panel.
  • Fit the Explorer list you already know. Forecasted Yield, Delegated Stake, and Trailing 90 Day Fees stay in the compare table; fee-versus-stake is an added read. Tooltips work on the column headers. Orchestrating detail and Your delegation are framed on the real account layout. See #837.
  • One vocabulary. List, mobile, and detail all mark the limiting side with “caps rewards,” and describe leftover room as “new stake still earns, up to +X%.” Detail uses the same twin fee / stake tiles as mobile, sized for the wide Orchestrating slot. Shared status icons with 803 (trend-up / filled circle / scale).

Open questions on this mockup

  • Single-round sort. Resist sorting the list on one unsettled round even if the subgraph makes it easy. Spikes are the attack the seven-round window is meant to blunt.
  • Old “Active” label. Today it means “in the capped orchestrator set.” After 2.0 that set goes away. Shipping fee/stake states under the old status teaches the wrong model.
