Helping people pick where to stake

Issue #802 ↗ Design decisions ↓

In Livepeer 2.0, a node’s new LPT rewards follow the smaller of two shares: how much work it does (fees), and how much stake sits behind it. Cash for that work stays whole. Stake unlocks more LPT only while the node is doing more work than it has stake for.

These mocks are for the moment of choice. If you are picking a node, you should feel where new stake still earns. If you are already bonded, you should know whether yours still has room, and what moving would cost. Plain language carries the story; the math waits in tooltips for anyone who wants it.

Color maps quantity (Livepeer brand palette). Fees · blue and Stake · green stay fixed; the state chip takes the color of whichever side is smaller. Green means stake, not “good.” Emissions are still settling, so the numbers here are shares of the network: how far a ceiling can still move.

Loading state mirrors row height:
  • Labels: “Room to earn,” “Full,” and “Balanced” name what happens if you stake here. A “caps rewards” tag marks the limiting side so the ceiling is visible at a glance.
  • Filter: “Earning now” keeps the list focused on nodes with real activity. “All nodes” keeps every address reachable when you need a specific one. It only changes which nodes appear. The columns stay the same.
  • Familiar numbers: Forecasted yield, Delegated stake, and Trailing 90D fees stay after the decision columns, quieter by type weight. Column order is the hierarchy; no group labels. Yield is a guess from current shares, so it informs the choice but never sets the order. On narrower laptops the quietest columns drop first (Node keeps, then 90D fees, then Delegated stake). Yield stays.

  • Where it sits: first item in the Orchestrating tab’s two-column grid, spanning both columns of the left content area. Existing stats stay below. The Delegate box stays in the right rail. Not a replacement for that box, and not a third column.
  • Two jobs: the card answers whether this node still has room (network fee share vs stake share). The right-rail box is the checkout for your amount: forecasted yield, inflationary rewards, and fee share for the LPT you type. Same word “fees,” different math.
  • Delegate on the card: optional. On desktop it moves focus to the amount box already on screen. Under 1200px it opens the existing bottom drawer. No stepped flow that hides the box.
  • Same slot, other states: Full and Balanced match the framed card width (shared with the Delegating page frame). Each one only swaps that top slot; the rail and stats stay put.
  • Wide-slot compare: twin fee/stake tiles carry the numbers (same idea as mobile). One short outcome line says what that means for new stake. No prose that restates the same %s again.
  • Collapsed breakdown: the open question is whether stake still earns. How the cut divides between node and delegators waits until someone is ready to commit.
  • Two pots: new LPT and USDC fees are separate rewards, so each lists its own split. A single “you get 92%” figure would blur pots that do not share a cut.

Design decisions

  • Network shares. How much new LPT the network mints is still being finalized, so these screens show how far a node’s reward ceiling can still move (for example from 2.3% toward 11.8%). That keeps the compare about opportunity while emissions settle.
  • Seven settled rounds. The list defaults to the last week of settled work. That window is harder to game, and it lines up with when rewards are paid. Deeper history has its own design later.
  • Room to earn / Full / Balanced. Those names speak to the stake choice on the compare list. Under 2.0 the old “Active” label loses its meaning with the capped set. On /delegating, the same stake-capped state reads “You’re earning” instead: the user already bonded, so the copy is about their stake, not leftover room for new stake.
  • Day one is a checklist. The launch card names where work comes from (gateways), then fees, then stake, with brand green and the Livepeer mark as the backdrop.
  • About 21 days to move. That is the working assumption here. If the protocol keeps instant transfers, the note comes out before ship. The wording is ready to follow the rule.
  • Fee and stake only. Honesty scores and validator set design are a separate project. This review stays with where stake still earns.
  • One vocabulary. List, mobile, and detail all mark the limiting side with “caps rewards,” and describe leftover room as “new stake still earns, up to +X%.” Detail uses the same twin fee / stake tiles as mobile, sized for the wide Orchestrating slot.
